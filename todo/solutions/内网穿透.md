## 可行性结论（先给答案）

**可行**。三条硬判据全部对得上，另有三个必须接受的限制。

### 为什么可行（每条都能在代码里找到判据）

1. **cpolar 支持 TCP 隧道（裸 TCP 透传）** ⇒ TLS 握手的两个端点仍是「手机端 ↔ HeAgent」，
   cpolar 只搬运密文字节。手机端的信任锚是 **SPKI pin**、不校主机名（`docs/errors.md` 第四节）
   ⇒ **pin 继续有效**，SAN 不需要为 cpolar 域名改动。
2. **服务端零改动**：agent 从本机连 `192.168.2.226:9201`，目的地址就是内网 IP
   ⇒ `WS_HOST=192.168.2.226` 不用改、不用重启；`external` 档本就强制 Bearer token。
3. **Host 不构成障碍**：`external` 档（`requires_auth=True`）刻意豁免 Host/Origin 白名单
   （`src/heagent/network/ws_host.py:248-253`：`external → _origin_violation` 直接返回 `None`）
   ⇒ cpolar 给的 `<n>.tcp.vip.cpolar.cn:<port>` 作为 Host 不会被 `403 host not allowed`。
   反向确认：若把档位退成 `lan`（`WS_LAN_NO_AUTH=true`），白名单复活（`src/heagent/network/origin.py:82-98`）
   且 `allowed_hosts` 只有 `WS_HOST` ⇒ 任何公网 Host 必 403（所以这个开关在穿透场景下永远不能开）。

### 三个必须接受的限制

1. **速率按档位封顶**：免费档 1 Mbps、基础档 2 Mbps；事件流与短回复够用，大输出/长文件会慢——这是限速，不是故障。
2. **~~随机 TCP 端口~~ → 已消除（2026-11-25 升级付费档）**：后台「预留 → 保留 TCP 地址」可分配**固定 host:port**，
   起隧道时用 `-remote-addr` 绑定 ⇒ 手机端地址一次写死，重连/重启不再需要改址。
   剩下唯一前提是这条预留记录不能删（删了地址重新分配）与脚本每次要带同一地址（脚本已缓存到 `.heagent/tmp/cpolar-remote-addr.txt`）。
3. **Windows 服务态不可用（本机实测）**：`cpolar service install` 需**管理员**权限；即便装上，服务以系统账户跑、
   读不到用户级 `cpolar authtoken` ⇒ 出现「服务 running、控制台隧道列表空、外部连不上」。
   ⇒ 常驻改用「登录时自启 + `cpolar_publish.py --watch --apply`」，服务态只作备选（见 `## 实施步骤` ⑥）。

### 什么情况下要改判

- 需要 24×7 更大带宽 ⇒ 换组网（Tailscale，无速率限制）或再升档（本账号已付费，档位以后台为准）。
- cpolar 要实名而你不想 ⇒ 换 ngrok（免费档 TCP 需绑卡）或公网 IPv6。
- ~~手机端无法改地址且必须固定入口~~ ⇒ **已解决（2026-11-25 付费档）**：预留固定 TCP 地址，见 `## 方案`。

## 细化（六项）

### 1. 标题

把 `192.168.2.226:9201`（`external` 档 wss + Bearer token）经 **cpolar TCP 隧道**发布，使非内网的手机端
App 可提交 run、订阅事件、走项目通道（手机端 = 收集端，即 `aihome-client` 这类原生客户端）。

### 2. 背景动机

- 服务端已是生产姿态（`.env:26-29`：`WS_HOST=192.168.2.226` + `WS_LAN_NO_AUTH=false`；`.env:51-52`：
  `WS_TLS_*` 成对 ⇒ `listener=external` / `tls=wss` / `auth=token`），但仅内网可达。
- HTTP 面默认只绑回环（`src/heagent/config/__init__.py:355`）且无认证 ⇒ 不能靠它对外。
- **无自有公网 IP / VPS** ⇒ 借 cpolar 的中转，本机不开放任何入站端口。

### 3. 验收判据（简版；命令全文见 `## 验收判据`）

- 外部网络（手机关 Wi-Fi 用 5G）跑 `python scripts/ws_tls_attest.py --host <cpolar域名> --port <端口> --cert .heagent/tls/cert.pem`
  → 四段 `[OK]` / 退出码 `0`；加 `--token` 出 `101`；错 pin 回 `pin_mismatch`。
- 一条命令版：`scripts/cpolar_selftest.ps1` 跑 `C1`–`C6`（四段承兑 / 无 token 必拒 / **pin 负向对照** /
  wss ping / wss submit / 内网不回归），退出码 `0` 即全过。
- 内网直连 `192.168.2.226:9201` 不回归（本方案不改服务端，天然成立，仍要复验）。

### 4. 落点

- 供应商侧：cpolar 账号 + Windows agent（无代码改动）。
- 宿主侧三份脚本（**分工固定，地址口径只有一套**）：
  `scripts/cpolar_tunnel.ps1` = 唯一「起隧道」实现（下载绿色版 / authtoken / `-remote-addr` 预留地址 / 三源回读）→
  `scripts/cpolar_selftest.ps1` = 一条命令跑六项外部判据（`C1`–`C6`）→
  `scripts/cpolar_publish.py` = 读同一份地址回填手机 App（`--apply` / `--watch`）。
- 手机端：连接地址改为 `wss://<n>.tcp.vip.cpolar.cn:<port>/api/runs/ws`，pin 与 token 原样照填；
  也可用 `scripts/cpolar_publish.py --apply` 自动回填（读同一份地址文件 → 写 App prefs）。

### 5. 规模

- S（≤ 半小时）：注册 5 min + 安装与起隧道 10 min + 外部验收 10 min。

### 6. 风险与前置（简版；全文见 `## 风险与前置`）

- 前置：cpolar 账号（是否需实名以控制台为准）；能读到用户级 `~/.heagent/setting.md` 的 `WS_AUTH_TOKEN`；
  一台外部网络的验收机器 + `cert.pem` 副本。
- 只用 **`cpolar tcp`**，不用 `cpolar http`（HTTP 隧道在边缘终结 TLS ⇒ 手机端必 `pin_mismatch`）。
- 别开 `WS_LAN_NO_AUTH`（公网等同裸奔、与 `wss` 互斥，且会让 Host 白名单复活直接 403）。

  `request_origin_violation` + `allowed_hosts(config)`（`network/origin.py:82-98`、`:109-150`）。

## 方案：cpolar TCP 隧道

链路：

```
手机端 --wss(端到端 TLS)--> <n>.tcp.vip.cpolar.cn:<port> --cpolar 边缘--> cpolar agent(宿主)
      --TCP--> 192.168.2.226:9201 (HeAgent WS listener, external + wss + token)
```

- cpolar 只做 L4 搬运：TLS 的证书与握手都在你的 HeAgent 上，cpolar 看不到明文。
- **档位额度**（2026-11-25 现读 `www.cpolar.com/pricing`）：免费档 **1 Mbps / 随机 TCP 端口 / 随机 URL 二级域名**，
  基础档 **99 元/年 起、2 Mbps**；**不限流量**、**HTTP / TCP 隧道均支持**。付费档解锁「预留」页
  （**保留 TCP 地址**、固定二级子域名），隧道条数与是否需实名官方页只给动态内容 ⇒ 以注册后控制台为准。
- **本用户已升级付费档（2026-11-25）** ⇒ 主形态改为「预留固定 TCP 地址 + `-remote-addr` 绑定」：
  入口不再漂移，手机端地址写死；TLS 仍端到端在本机，pin 与 SAN 不受影响（客户端只认 pin、不校主机名）。
- 官方文档（保留地址的唯一权威）：<https://www.cpolar.com/blog/reserved-tcp-address> ——
  后台 `预留` → `保留 TCP 地址` → 选地区 + 填描述 → 点 `保留`；
  命令行用 `-remote-addr=<分配的 host:port>`，配置文件里键是 `remote_addr`（下划线），二者不要混。

## 实施步骤（照着敲）

> 子命令名以你装的版本 `cpolar help` / `cpolar tcp --help` 为准（下列为通用形态）。

### ① 注册并取 authtoken

- 官网注册、邮箱激活，登录后台，在「验证 / Authtoken」页复制 authtoken。
- 判定：能看到自己的「隧道」列表页 + authtoken 已复制。

### ② 宿主安装 cpolar（两条路，任选一条）

**推荐：用仓库脚本装绿色版**（不写注册表、卸载 = 删目录；默认落在 `%LOCALAPPDATA%\cpolar`）：

```powershell
# 只装配不起隧道：下载 + 解压 + 校验 cpolar.exe，无 token 也能跑
powershell -ExecutionPolicy Bypass -File scripts\cpolar_tunnel.ps1 -CheckOnly

# 换目标目录 / 强制重下 / 钉版本（默认钉 3.3.12：新版本若下载 404 就显式传页面上的版本号）
powershell -ExecutionPolicy Bypass -File scripts\cpolar_tunnel.ps1 -CheckOnly -Dir D:\cpolar
powershell -ExecutionPolicy Bypass -File scripts\cpolar_tunnel.ps1 -CheckOnly -Reinstall -Version 3.3.12
```

- `-CheckOnly` 只做装配（下载 → 解压 → 找 `cpolar.exe` → 写 authtoken 若已传），**不起隧道**；
  看到 `[cpolar] -CheckOnly：已装配到 <目录>，未起隧道` 即成功，别把它当成「隧道已就绪」。
- 解压后会递归找 `cpolar.exe`，找不到直接报「下载内容可能不是官方包」（fail loud，不静默降级）。

**或者：装官方 Windows 安装包**（需要 `cpolar` 进 PATH 时用这条）

- 官网「下载」页取 **Windows** 版安装包；装完**新开**一个 PowerShell（让 PATH 生效）。
- 判定：`cpolar version` 打印版本号。

### ③ 写入 authtoken

```powershell
cpolar authtoken <你的 authtoken>
```

- 作用：写进**当前用户**配置（`~\.cpolar\cpolar.yml`）；之后建的隧道才算到你账号、才进控制台列表。
- 判定：命令无报错。
- 已写过就不必再传 `-Authtoken`：`cpolar_tunnel.ps1` 会先从 `~\.cpolar\cpolar.yml` 回读
  （`Get-StoredAuthtoken`），读不到才要求传参。

### ④ 起 TCP 隧道（付费档：绑定保留 TCP 地址）

先在后台拿地址：登录 cpolar 后台 → `预留` → `保留 TCP 地址` → 选地区（如 `cn_vip`）+ 填描述 → 点 `保留`
⇒ 得到形如 `1.tcp.vip.cpolar.cn:20046` 的**固定** host:port（这条预留记录删掉就会重新分配，别删）。
官方口径见 <https://www.cpolar.com/blog/reserved-tcp-address>。

```powershell
# 推荐：本仓一键脚本（下载绿色版 + 写 authtoken + 绑定预留地址 + 后台起 + 回读公网地址）
powershell -ExecutionPolicy Bypass -File scripts\cpolar_tunnel.ps1 -Authtoken <token> `
    -RemoteAddr 1.tcp.vip.cpolar.cn:20046 -Detach

# 等价的裸命令（先手工跑通，再交给脚本常驻）
cpolar tcp -remote-addr=1.tcp.vip.cpolar.cn:20046 192.168.2.226:9201
```

- 地址只传一次：脚本把它缓存到 `.heagent/tmp/cpolar-remote-addr.txt`，之后重跑不必再带 `-RemoteAddr`。
- 预留地址属于特定区域时，若默认区域连不上，加 `-Region cn_vip`（裸命令对应 `-region=cn_vip`）。
- 回读次序（三份 cpolar 脚本共享同一套口径）：先打**本地管理面** `http://127.0.0.1:9200/api/tunnels`
  （cpolar web UI 默认 9200，兼容 4040；隧道活着必列 `public_url`）；3.3.12 的日志只吐控制通道 debug 行
  （`Pong from Switch Server` 只证明 authtoken 有效），所以日志里的 `Forwarding` 行不可靠，只作兜底；
  最后退到 `-RemoteAddr` 保留地址（最不该漂移的那一个）。三路都空才打印诊断块。
- 回读成功即落一份 `.heagent/tmp/cpolar-address.txt`（`host:port`，无 scheme）= **地址共享契约**：
  `cpolar_selftest.ps1` 与 `cpolar_publish.py` 都从这里取地址 ⇒ 不要手改，也不要另存第二份。
- 免费形态（不传 `-RemoteAddr`）：`cpolar tcp 192.168.2.226:9201`，端口随机且会漂移，只用于「先证明能通」。
- ⚠️ 本地地址写 `192.168.2.226`，**不要写 `127.0.0.1`**：`external` 档刻意不注册回环监听，写回环等于
  转给没人监听的端口（现象 = 外部连上就 reset / 握手失败）。
- ⚠️ **不要用 `cpolar http …`**：HTTP 隧道在 cpolar 边缘终结 TLS ⇒ 手机端必 `pin_mismatch`。
- 期望输出末尾有一行 `[cpolar] 公网地址：tcp://<host>:<port>（来源：…）`，括号里会标明它是从
  **管理面 / 预留地址 / 日志** 哪一路读到的（3.3.12 前台裸跑时也可能打印 `Forwarding  tcp://… -> 192.168.2.226:9201`，
  那是同一件事的另一种呈现）。绑了保留地址时，这里**必须**就是预留的那一对；不一致 = 绑定没生效，
  先核 `-remote-addr` 拼写与区域。
- 转发目标默认从仓库 `.env` 的 `WS_HOST:WS_PORT` 现读（`Get-DefaultTarget`）⇒ 只为一次试跑改地址时用
  `-Target <host:port>`，别去动 `.env`。
- 已有 cpolar 进程时脚本**默认停手并退 `2`**（提示加 `-KillExisting`）：两条隧道抢同一入口的现象是
  「间歇性连不上」，所以不自动杀进程。
- 不加 `-Detach` = 前台运行（Ctrl+C 结束，便于目视 `Forwarding` 行）；加了才写
  `tunnel-<时间戳>.log` / `.err`（每次独立文件名，避免旧进程占句柄）并回读公网地址。
- `-Protocol http` 能跑但会打一行 WARNING（cpolar 侧终结 TLS ⇒ 手机端必然 `pin_mismatch`）⇒ 只作诊断用。
- 起隧道前会探一次目标端口：`[cpolar] <host>:<port> 当前没有监听（…）` 只是 `Write-Warning`，
  **不阻断**（隧道照样建立，但访问会失败）⇒ 看到它先查服务端是否真在跑。
- 退出码三分：`0` 成功 / `1` 运行失败 / `2` 参数或前提缺失（已有进程、`-RemoteAddr` 形状不对、authtoken 写入失败）。
  写自动化时按这个判，别只看 `cpolar` 子进程是否存活。
- 若报「只接受端口 / invalid address」，走回退形态（管理员 PowerShell）：

```powershell
netsh interface portproxy add v4tov4 listenport=19201 listenaddress=127.0.0.1 connectport=9201 connectaddress=192.168.2.226
cpolar tcp 19201
```

- 回退后链路多一跳：`cpolar → 127.0.0.1:19201 → (portproxy) → 192.168.2.226:9201`。

### ⑤ 外部网络验隧道（先证字节流通了，再验契约）

- 在**外部网络**的机器（手机热点下的笔记本）上，且该机器有 `.heagent/tls/cert.pem` 副本：

```bash
python scripts/ws_tls_attest.py --host <n>.tcp.vip.cpolar.cn --port <port> --cert .heagent/tls/cert.pem
```

- 期望四段 `[OK]`、退出码 `0`（第 4 段 = 无 token 必须 `403`）。这里就红 ⇒ 先查「本地地址是否写成回环」
  与「端口是否抄错」，再按 `## 排障对照表`。
- 通过后加 `--token "<WS_AUTH_TOKEN>"` 再跑一次，期望出现 `101`（token 不进任何输出）。
- 想一条命令把「四段承兑 + 无 token 必拒 + pin 负向对照 + wss ping + wss submit + 内网不回归」全跑完：
  `powershell -ExecutionPolicy Bypass -File scripts\cpolar_selftest.ps1`（六项见 `## 验收判据` 的 C1–C6 表）。

### ⑥ 常驻（三档，按可靠性排序）

**推荐档：登录自启 + `--watch` 守护**（2026-11-25 实测：服务档在本机装不上，见下）

```powershell
# 1) 起隧道（-KillExisting 保证只有一条，避免两条抢同一入口）
powershell -ExecutionPolicy Bypass -File scripts\cpolar_tunnel.ps1 -Detach -KillExisting

# 2) 守护：隧道掉了重起、地址变了回填 App（30 s 一轮，--interval 可调）
.venv\Scripts\python.exe scripts\cpolar_publish.py --watch --apply
```

- 把这两条放进「任务计划程序 → 登录时触发」，就是本机实际可用的常驻形态。
- 判定：控制台/管理面隧道列表里有这条隧道 **且** `cpolar_publish.py` 打印的 `wss://host:port` 与
  `.heagent/tmp/cpolar-address.txt`（无 scheme 的 `host:port`）逐字相同（本机 `cpolar service status`
  只说明进程在，不能证明隧道建立了）。

**服务档（可选，需管理员；本机装不上）**

```powershell

cpolar service start
cpolar service status
```

- 两个凹点：
  ① `service install` 要**管理员权限**，普通 PowerShell 直接失败；
  ② 服务以**系统账户**运行，读不到 ③ 写进当前用户目录的 authtoken ⇒ 现象「running 但控制台隧道列表空、
  外部连不上」。
- ⇒ 本机结论：**不装服务态**，用上面的「登录自启 + `--watch`」；若一定要服务态，得把 token 写进服务实际读取的配置
  （以 `cpolar help` 与安装参数为准）后再验隧道列表。

**手工档**：前台 `cpolar tcp …` + 单独的终端窗口（调试期用，关窗即断）。

### ⑦ 手机端改址

- `wss://<n>.tcp.vip.cpolar.cn:<port>/api/runs/ws`（提交）/ `.../api/runs/<run_id>/ws`（订阅）。
- pin 与 token 照填；供应商域名不必进 SAN（客户端只认 pin、不校主机名）。
- 付费档已绑保留地址 ⇒ 手机端地址**写死一次即可**（`wss://<预留 host>:<预留 port>/api/runs/ws`）；
  仍建议客户端保留改址入口（换预留记录 / 换区域时才用得上），pin 永远不变。

### ⑦b（可选）把地址自动回填进手机 App

手改一次 pref 就要重新输地址；`scripts/cpolar_publish.py` 把这一步自动化，它只做三件事：
读地址 → 有变化才写 → 可选常驻守护。

```powershell
.venv\Scripts\python.exe scripts\cpolar_publish.py                     # 只打印当前公网地址（wss://host:port）
.venv\Scripts\python.exe scripts\cpolar_publish.py --apply             # 地址变了才写进 App，revision+1
.venv\Scripts\python.exe scripts\cpolar_publish.py --restart --apply   # 先重起隧道再回填（重起交给 cpolar_tunnel.ps1 -KillExisting）
.venv\Scripts\python.exe scripts\cpolar_publish.py --watch --apply     # 常驻：隧道掉了重起、地址变了回填
.venv\Scripts\python.exe scripts\cpolar_publish.py --watch --apply --interval 15   # 缩短守护轮询（默认 30 s）
.venv\Scripts\python.exe scripts\cpolar_publish.py --check-san --apply  # 额外提示对面证书是否覆盖该主机名（从不阻断）
.venv\Scripts\python.exe scripts\cpolar_publish.py --address <host:port> --apply   # 应急：跳过回读，显式指定
```

- 退出码：`0` 成功 / `1` 拿不到地址或写 App 失败 / `2` 参数不合法；`--timeout`（默认 60 s）只影响「等地址」的耐心。

- **起隧道不在这个脚本里**：它直接调 `cpolar_tunnel.ps1 -Detach`，authtoken / `-remote-addr` /
  回读只有那一份实现 ⇒ 三份脚本的地址口径不会分叉。
- 地址回读次序：管理面 `/api/tunnels` → `.heagent/tmp/cpolar-address.txt` → 预留地址 → 最新隧道日志。
- 写 App 走 `adb`（容器 `aihome-android-verify` → 模拟器 `host.docker.internal:7555`，包
  `com.aihome.client`）：改 `shared_prefs/connection_settings.xml` 的 `websocket_endpoint`、`revision` +1，
  写完 `am force-stop` 并回读校验 ⇒ 下次打开 App 生效（不做热改，免得留下半截配置）。
- **不判 SAN，也从不因此拒写**：客户端只认 SPKI pin、不校主机名（见「为什么可行」第 1 条），cpolar 域名
  不在 SAN 里照样能连；`--check-san` 只在你要给「会校主机名」的其它客户端排查时用，那时才需要
  `heagent tls issue --san <host>`（唯一签发入口）重签叶证书并重启 heagent。
- 判据：`--apply` 后
  `docker exec -it aihome-android-verify adb -s host.docker.internal:7555 shell run-as com.aihome.client cat shared_prefs/connection_settings.xml`
  里 `websocket_endpoint` == 当前公网地址、`revision` 比上次大 1；App 重开即收到 `hello`。

### ⑧ 回滚

```powershell
cpolar service stop                                              # 前台跑的按 Ctrl+C
netsh interface portproxy delete v4tov4 listenport=19201 listenaddress=127.0.0.1   # 仅走过回退形态时
```

- 服务端一直没动 ⇒ 回滚只影响外部可达性，内网零影响。

## 验收判据

### 一条命令版（推荐）：`scripts/cpolar_selftest.ps1`

```powershell
powershell -ExecutionPolicy Bypass -File scripts\cpolar_selftest.ps1                   # 六项全跑
powershell -ExecutionPolicy Bypass -File scripts\cpolar_selftest.ps1 -SkipSubmit      # 不真跑一轮 agent（C5 记 SKIP）
powershell -ExecutionPolicy Bypass -File scripts\cpolar_selftest.ps1 -SkipSubmit -SkipInternal
powershell -ExecutionPolicy Bypass -File scripts\cpolar_selftest.ps1 -Address 5.tcp.cpolar.cn:10176 -Token <token>
```

| 编号 | 判据 | 期望 | 可跳 |
| --- | --- | --- | --- |
| C1 | 四段承兑（绑定面 / TLS 握手 / pin 对账 / 认证闸门，带 token） | `exit 0`、四段 `[OK]` | — |
| C2 | 无 token 必须被拒（`external` 档） | 回 `403` 且 `exit 0` | — |
| C3 | **pin 负向对照**（拿 `ca.pem` 当本地叶证书，SPKI 必不同） | **必须失败**且输出含 `pin`（防恒绿） | 缺 `ca.pem` 自动 SKIP |
| C4 | 业务连接 `wss ping`（`ws_manual_probe.py`，`--insecure`） | 收到 ack | — |
| C5 | 业务提交 `submit`（真跑一轮 agent，10 s 窗口） | 拿到 run | `-SkipSubmit` |
| C6 | 内网直连不回归（对 `.env` 的 `WS_HOST:WS_PORT` 重跑承兑） | `exit 0` | `-SkipInternal` |

- 地址四级回读（与另两份脚本同序）：管理面 `/api/tunnels` → `.heagent/tmp/cpolar-address.txt` →
  预留地址 `.heagent/tmp/cpolar-remote-addr.txt` → `%LOCALAPPDATA%\cpolar\tunnel*.log` 的 `Forwarding` 行；
  四路全空就打印诊断块（管理面可否连、`/api/tunnels` 原文、cpolar 进程、最近 5 个日志文件）并以 `2` 退出。
- token 默认读用户级 `~\.heagent\setting.md` 的 `ws_auth_token`；python 默认 `.venv\Scripts\python.exe`，
  里没有 `websockets` 包直接退 `2`。
- 退出码：`0` 全过（SKIP 不算失败）/ `1` 有 FAIL / `2` 前提缺失（python / token / 地址 / `cert.pem`）
  ⇒ **`2` 不是判据失败**，先补前提再重跑。
- 位置说明：这六项在**宿主**上跑就会穿公网地址往返，能证「入口可达 + 契约」；但「换网络环境」这件事
  仍需在外部网络（手机关 Wi-Fi 用 5G）用下面的第 1/2 条各跑一次。

### 手工清单（逐条）

全部从**外部网络**执行（手机关 Wi-Fi 用 5G，或别的网络下的机器），`<HOST>`/`<PORT>` 取 ④ 的
`[cpolar] 公网地址` 那一行（等价于 `.heagent/tmp/cpolar-address.txt` 的内容）：

1. **四段承兑**（绑定面 / TLS 握手 / pin 对账 / 无 token 必须 403）：
   ```bash
   python scripts/ws_tls_attest.py --host <HOST> --port <PORT> --cert .heagent/tls/cert.pem
   ```
   期望：四段均 `[OK]`，退出码 `0`（`--expect-unauth` 默认 `403`，正是 `external` 档的正确期望）。
2. **认证正例**（追加第 ⑤ 段 101）：
   ```bash
   python scripts/ws_tls_attest.py --host <HOST> --port <PORT> --cert .heagent/tls/cert.pem \
     --token "<WS_AUTH_TOKEN 明文>"
   ```
   期望：出现 `101`，token 值不进任何输出（只报「已提供（长度 N）」）。
3. **pin 逐字一致**：`heagent tls fingerprint --format pin` 与手机端内置值相同（`text`/`json`/`pin` 三格式同源）。
4. **端到端**：手机端收到 `hello`；提交一条 prompt 能收到 `event` 流并走到 `done`。
5. **反向判据**：无 token 必须 `403`；故意喂错 pin 必须回 `pin_mismatch`。
6. **不回归**：内网直连 `192.168.2.226:9201` 仍通。
7. **地址固定性（付费档专属）**：`Stop-Process -Name cpolar` 停隧道 → 重跑 `cpolar_tunnel.ps1 -Detach`
   → 公网 `host:port` 必须与上一轮**逐字相同**，手机端不做任何改动即能连上。
8. **速率体感**：跑一条中等长度回复记录端到端耗时；接近当前档位带宽上限（免费 1 Mbps ≈ 128 KB/s、
   基础档 2 Mbps ≈ 256 KB/s）属限速，不判故障。
9. **回填闭环（只在用了 ⑦b 时）**：`cpolar_publish.py --apply` 后 App prefs 的 `websocket_endpoint`
   == 当前公网地址；重开 App 收到 `hello`；隧道重起后 `--watch --apply` 能自动跟随（地址没变则不重写）。

> 更严可选：加 `--refused 127.0.0.1:<PORT>` 显式要求「本机回环必须拒绝」；第 ⑤ 段对账可加
> `--status-url http://127.0.0.1:9101/api/status`（在宿主跑）比对 `listeners[].tls.spki_sha256`。

| 外部验收第 ① 步基线就红 | 服务端自身/证书材料问题，与 cpolar 无关 | 先修服务端，重跑基线 |

## 风险与前置

- **前置**：cpolar 账号（是否需实名以控制台为准）；能读到用户级 `WS_AUTH_TOKEN`；外部网络验收机 + `cert.pem` 副本。
- **风险① 速率**：带宽按档位封顶（免费 1 Mbps、基础档 2 Mbps），事件流与短回复够用；大输出体验差 ⇒ 选型代价，不是缺陷。
- **风险② 地址漂移 → 已缓解（付费档）**：绑保留地址后入口固定；残余风险 = 预留记录被删（地址会重新分配）、
  账号降级失去预留能力、或忘了带 `-remote-addr` ⇒ 三种都表现为「地址变了」，按排障表处置。
- **风险③ 供应商可见性**：cpolar 只见密文（TLS 端到端），但**连接元数据**（谁连、何时、多少流量）在它那里。
- **风险④ 单点**：cpolar 侧故障/限流 ⇒ 外部立即不可达；内网与 CLI 不受影响。
- **风险⑤ 免认证开关**：`WS_LAN_NO_AUTH=true` 会让 Host 白名单复活（公网地址必 403）且等于裸奔，永远别开。
- **风险⑥ HTTP 面板**：若要发布 9101，须另加认证反代，且它不在安全边界内（可改项目配置）。
- **风险⑦ 常驻依赖登录会话**：本机不装服务态 ⇒ 用户注销 / 未登录时隧道不在；
  机器长期无人值守要另配「开机即登录 + 任务计划」，或改服务态并解决 authtoken 可见性。
- **不随隧道暴露的东西**：CLI 旁路 `/api/cli/ws` 只挂回环 listener（非回环绑定启动即打
  `ws event=cli_bypass_skipped reason=non_loopback_listener`）⇒ 终端内容不外溢，属预期。
