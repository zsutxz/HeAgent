## Findings

### 实现类

- **F1（medium，已修）提交端点的连接额度缺口**：新建的 `WS /api/runs/ws` 首版**没有任何连接上限**——Uvicorn 的
  `limit_concurrency` 不约束 WS 连接（Epic 54 实测），而 run 端点与 CLI 旁路各有额度。对外模式下等于「拿着
  token 就能开无限条空闲连接」。处置：`_SubmissionSlots`（检查 + 登记同一同步方法，A9③ 口径），e2e 判据
  覆盖「满额回 `rate_limited`」与「关闭后归还」。
- **F2（medium，已修）帧上限按原始字符数定，合法输入不可用**：`WS_MAX_INBOUND_CHARS` 初版
  `MAX_PROMPT_CHARS + 1024`；`json.dumps` 默认 `ensure_ascii=True` 下 32 768 个汉字会膨胀成约 197 K 字符，
  **合法的最大 prompt 被协议层以 1009 掐断**（e2e 实测踩到），而 HTTP 侧同一 prompt 完全可用。处置：按
  最坏转义重算，判据落在「最大 prompt 经 WS 可提交」。
- **F3（medium，已修）凭证诊断面自相矛盾**：`USER_ONLY_SETTING_KEYS` 首版对所有扫描来源放行 ⇒ 项目 `.env`
  里写的 `WS_AUTH_TOKEN` 会被面板当成合法键，而它**并不生效**。处置：放行只对用户层生效，并补「写错位置
  仍报未知键」判据。
- **F4（medium，已修）配置错误在命令层吐 traceback**：Pydantic 校验错误从 `build_ws_server_config` 原样上抛。
  处置：`WsConfigError` + ClickException + `embedded_http_error_message` 映射，CLI 级三例判据。
- **F5（medium，已修）传输层互相依赖**：`HttpRunConflictError` 住在 `http_server`，逼 `ws_server` 反向导入。
  处置：迁入 `http_protocol`（`http_server` re-export），并加架构契约断言钉死。
