# 架构脊柱质量准则评审 - Epic 49 HTTP 网页访问

评审视角：BMad 架构脊柱质量准则。对象：`ARCHITECTURE-SPINE.md`（Epic 层级、
状态为 `final`）。证据：Epic 49 的 `brief.md` / `epics.md`、`docs/frame.md`，以及
当前 `src/heagent/` 棕地项目边界。

## 结论

**通过但有发现。** 脊柱拥有清晰的“传输层加注入”范式，固定了关键的所有权决策（组合根、单会话、
每次运行的 loop、可重放 SSE），保持项目治理链，并显式延后远程部署和持久化。它已接近可供构建的
基底，但在 Story 使用前仍应解决以下发现：两条既有规则要么与棕地惯例冲突，要么留下真实的跨 Story
契约歧义；另有两条强制 NFR 未出现在已声明的能力覆盖中。

## 发现

### H1 - AD-1 的允许依赖规则与所需的棕地复用相矛盾

AD-1 表示 `network/` **只能**依赖 HTTP 协议模型、标准 asyncio/运行时、ASGI 框架和注入协议。
但 AD-6 要求复用 `network.exposure`，AD-9 要求既有 `safe_logging`，当前 TCP 传输层也已导入二者
（`src/heagent/network/tcp_server.py`；`docs/frame.md` 将 `safe_logging` 描述为零 `heagent` 依赖的共享
日志边界）。按字面实现无法同时复用这些机制并遵守 AD-1。

**所需脊柱决策：** 显式允许传输安全的共享叶子 `heagent.network.exposure` 和
`heagent.safe_logging`（或声明 HTTP 不得复用它们）。前者确认既有 TCP 边界及已声明需求；不得把选择
留给构建者。

### H2 - 未决定完成保留期与订阅者终止语义

AD-3 规定 HTTP 服务拥有运行记录、任务、缓冲和订阅；AD-4 表示支持重放；AD-5 表示关停关闭订阅。
脊柱没有定义何时终止*正常* SSE 订阅，也没有定义何时可淘汰终态运行记录和事件缓冲。Story 49-3 要求
SSE 在完成/失败后结束，而 Story 49-4 要求重连重放；没有保留/终止规则时无法一致实现。

**所需脊柱决策：** 声明终态事件在配置的有界保留窗口内可重放，每个活动 SSE 流在重放终态事件后结束，
且只在窗口结束后淘汰记录/缓冲（之后给出稳定的未知/过期运行结果）。可采用等价语义，但必须在此固定
所有者和边界。

### M1 - 脊柱声明的约束中遗漏 NFR4 和 NFR8

frontmatter 的 `binds` 列表遗漏 NFR4（独立 `AgentLoop`，不共享可变运行状态）和 NFR8（SSE/断线/取消/
关停释放全部任务/订阅资源）。二者都是 `epics.md` 中的驱动约束，也是 49-2、49-3 和 49-4 的 Story
可追溯性要求。AD-3 和 AD-5 部分体现了它们，但遗漏使顶层覆盖声明不完整，削弱下游验证。

**所需脊柱修改：** 将 NFR4 和 NFR8 加入 frontmatter 的 `binds`、相关 AD 约束，以及能力映射行或显式映射。

### M2 - 生命周期规则未决定超时语义

AD-5 要求关停硬超时，AD-6 要求运行限制，但均未说明运行超时是否取消任务、发送何种终态事件/错误，或关停
取消是否优先于并发的运行超时/DELETE。Story 49-4 将 `timed_out` 命名为独立状态。这是跨 Story 状态机决策，
不是实现细节。

**所需脊柱决策：** 固定终态优先级和可观察映射，例如显式 DELETE/关停或运行超时均请求取消任务；第一个终态
转换获胜；仅发送一个 `cancelled` 或 `timed_out` 事件，并在 `finally` 中释放唯一的在途槽位。

## 建议解决顺序

1. 修改 AD-1，允许两个获准的传输安全共享叶子。
2. 增加一条显式的终态保留/订阅规则和一条超时/取消优先级规则。
3. 修复 frontmatter、AD 约束和映射中的 NFR4/NFR8 可追溯性。
