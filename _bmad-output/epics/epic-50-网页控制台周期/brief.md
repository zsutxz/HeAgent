## 1. 产品目标

把网页入口从「一个进程 = 一个目录的一次性聊天页」升级为**本机控制台**：

1. **项目管理**：在网页里添加已有目录、切换、移除**项目**（项目 = 一个目录，其 `.heagent/` 是该项目的
   状态根：会话 / 记忆 / 技能 / ledger / runs）；不同项目的会话与记忆互不串味。
2. **配置管理**：在网页里查看与编辑 HeAgent 配置（模型与路由、上下文与记忆、沙箱、限额、日志、cron 等），
   每项显示**有效值 + 来源**（系统环境变量 / 项目 `.env` / 全局 `~/.heagent/.env` / 字段默认），并遵守既有
   优先级；**凭证只显示"已配置/未配置"与掩码，永不回传明文**。
3. **ChatGPT 式交互**：左侧项目/会话栏（新建对话、切换、重命名、删除、最近排序），右侧对话区，设置入口
   在独立面板；保留 Epic 49 已有的流式回答、工具活动、停止/重连体验。

## 2. 核心用户场景

| 场景 | 用户操作 | 预期结果 |
|---|---|---|
| 多项目工作 | 登记已有目录并在项目列表中切换 | 展示所选项目的会话，既有运行仍绑定原项目 |
| 延续对话 | 新建对话，稍后刷新页面或重启服务 | 能读取已保存的消息并继续对话 |
| 整理历史 | 重命名、删除会话或移除项目登记 | 影响范围清楚，删除会话需确认，移除登记保留磁盘数据 |
| 理解配置 | 打开项目设置 | 看见有效值、来源、可写性与受限原因 |
| 调整配置 | 保存允许编辑的项目设置 | 保存成功后对新运行生效，当前运行保持原配置 |

## 3. 现有基础与规划影响

以下作为规划依据，具体装配路径和接口在架构阶段再次核验。

| 事实 | 依据 |
|---|---|
| 网页入口**一个进程固定一个工作区**：handler 启动时以 `os.getcwd()` 固定 `workspace_root`，并一次性构建 `SkillStore()` / `FactStore()` / `ProfileStore()` / soul；每个 run 的 loop 再以 `context_dir=os.getcwd()` 装配 | `cli_http.HttpAgentHandler.__init__` / `.new_loop()`；`cli._build_loop`（其中 `JobStore()` 亦 cwd 相对） |
| 全部 `.heagent/*` 状态根是 **cwd / home 相对**：sessions / ledger / runs / memory / skills | `tools/path_safety.build_internal_state_dirs()`（`Path.cwd()` + `Path.home()`）；各 store 默认 `base_dir` |
| 网页运行**不写会话文件**；会话投影与 SSE 缓冲属于进程内状态，不能替代跨服务重启的会话恢复 | `cli_http.HttpAgentHandler.new_loop()`；`docs/frame.md` 4.17 |
| 配置优先级：系统环境变量 > 项目 `.env` > `~/.heagent/.env` > 字段默认；**组装期冻结为 `ResolvedRuntimeConfig` 快照，业务执行只读快照** | `config.py`（`env_file=[GLOBAL_CONFIG_FILE, ".env"]`）；`agent/loop.py` / `engine/container.py` 的 Phase 1 快照 |
| 入口安全立场：无认证、无 TLS、回环 + 同源防线，**非安全边界** | `docs/frame.md` 4.17 与五；`network/exposure.py` |

⇒ 两条硬结论：**(a)**「打开不同项目」不是加个下拉框，而是要把「工作区」提升为一等参数、穿透 engine / stores /
policy / sandbox 会话目录；**(b)**「配置改动」只能对**新 run**生效（快照语义），网页不得声称"改完立即生效"。

## 4. 功能范围

- **FR-1 工作区一等化**：以 `workspace_root` 为项目身份，按项目构造 engine 与记忆/技能/会话存储；同一个
  服务进程可服务多个项目，运行按项目绑定围栏、沙箱会话目录与状态根。
- **FR-2 项目注册表**：项目列表（含最近打开）、登记已有目录 / 切换 / 重命名显示名 /
  移除登记（**不删目录**）；路径规范化，明确重复登记、目录失效与非目录路径的处理。
- **FR-3 会话持久化 + 侧栏数据面**：项目内多会话（新建 / 切换 / 重命名 / 删除 / 继续），复用既有
  `SessionStore`（CLI 与 GUI 已在用），落到**该项目**的 `.heagent/sessions/`。
- **FR-4 配置读取**：分类列出可配置项的有效值 + 来源 + 是否可写（被系统环境变量覆盖的项标记为只读）。
- **FR-5 配置写入**：经 pydantic 校验后原子写项目 `.env`，写前备份、检测外部修改冲突、写后回读校验，
  记录审计日志（**不含值**）；生效语义 = 下一次 run。
- **FR-6 网页 UI**：ChatGPT 式两栏布局（项目/会话侧栏 + 对话 + 设置面板），危险项二次确认，来源徽标。
- **FR-7 安全与验收**：写通道的防线、凭证零回传测试、非安全边界声明、验收清单（含"跨项目不串味"）。

## 5. 范围边界

- 多用户 / 账号 / 权限体系、TLS、反向代理、公网或局域网暴露（沿用「须 OS 级沙箱/隔离」的立场）。
- 运行中热切换模型 / 工具策略；配置改动只对新 run 生效，不做当前运行的动态重配置。
- MCP 管理 UI、工具审批 UI（Epic 49 已明确不在网页入口做）。
- 删除项目目录、Git 操作、文件浏览器（项目内文件操作仍走既有工具链）。
- 创建项目目录、浏览器直接读写任意宿主文件。
- SSE 事件全量持久化、服务重启后自动续跑中断任务；本周期持久化的是可恢复的对话数据。
- ~~扩大跨项目并发运行能力；沿用既有运行限额，多项目切换不等于并行运行。~~
  **2026-09-24 修正（脊柱 D9，原评审 F4）**：多项目**并行运行**是本周期**有意采纳**的语义 ——
  在途上限 = 项目数 × `HTTP_MAX_INFLIGHT_RUNS`（默认项目上限 32 ⇒ 最多 32 个并发 run），
  跨项目不共享在途名额、不做全局调度；每项目内部仍沿用既有运行限额（单运行 / 会话在途保护）。
  原「多项目切换不等于并行运行」的表述**作废**。仍**不做**的是：跨项目共享名额、全局调度、
  全局并发软上限（已登记为已知缺口）。

## 6. 安全与一致性约束

1. 网页入口**无认证、无 TLS、非安全边界**；一切「配置编辑」能力都等于**把该能力交给任何能连上该端口的人**
   （回环也视为不可信）。→ UI 必须显示该事实，不得给人「网页是安全控制台」的错觉。
2. **凭证保护**：网页不提供密钥输入；读取只回「已配置/未配置 + 掩码」，短密钥不得因展示尾部而暴露全文。
   写入拒绝凭证字段（包括 `*_API_KEY` / `*_API_KEYS`）；响应、校验错误、日志与审计均不得回显明文。
3. **配置编辑通道**只修改项目 `.env` 的允许键，不接受任意文件路径。可写项从 `Settings.model_fields` 中
   选择明确允许编辑的子集，处理字段别名，排除凭证与服务启动控制项；未知键一律拒绝。
4. 项目根路径是本机任意目录 ⇒ 网页因此能"读取该目录作为工作区"。这是**既有限制面**的延伸（CLI 也是 cwd 决定），
   但必须在文档与 UI 中声明：**网页不是权限边界**。
5. 复用 Epic 49 的同源防线（Host / Origin / 拒绝 forwarded），并为写通道**额外**要求本机回环来源。
6. 新增持久化写入包括项目登记、会话及运行状态、项目 `.env`、配置备份和审计记录；各类写入须明确固定位置与允许操作。
   备份按敏感配置处理，不向网页提供下载；保存失败必须显式报告并保证原配置可恢复。
7. 项目切换使用显式工作区参数，不修改进程 cwd 或进程环境变量；项目级状态保持独立，既有全局资源须标明共享属性。
8. 同一会话的网页与 CLI 并发写入须检测冲突并显式拒绝覆盖；运行中会话的删除也须受冲突检查约束。
9. 系统环境变量覆盖的项只读；全局值与默认值允许通过项目配置覆盖。需要重启服务的字段只展示，不纳入下一次运行生效的编辑通道。

## 7. 本轮规划基线

以下将原建议收敛为重规划基线，供架构与验收细化；不代表架构已冻结或实现已完成。

| # | 决策 | 本轮基线 | 影响 |
|---|---|---|---|
| D1 | 配置写入面：仅项目 `.env` / 也允许 `~/.heagent/.env` / 完全不允许网页写 | **仅项目 `.env`**，全局文件只读 | 全局文件对所有项目生效，误改影响面大 |
| D2 | 项目切换粒度：每请求带 `project` 参数（无服务端状态）vs 服务端"当前项目" | **每请求带参**（无状态、可并发、与既有单运行约束正交） | 影响 API 形状与缓存（engine/stores 可复用池化） |
| D3 | "新建项目"语义：只登记已有目录 vs 允许创建目录 + 初始 `.heagent/` | **只登记**（不替用户在磁盘上建目录） | 后者是新增的宿主写面 |
| D4 | 配置写入开关统一为 `HTTP_CONSOLE_WRITE_ENABLED` | **默认关闭**，由服务启动配置决定，网页不能自行开启 | 控制配置编辑，不控制 HTTP 服务启动 |
| D5 | 会话是否与 CLI 同库（`.heagent/sessions/`） | **是**（复用 `SessionStore`，同项目同库） | 网页与 CLI 交替使用同一会话文件，需处理并发与"谁在写" |

## 8. 分阶段交付建议

| 阶段 | 交付结果 | 检查点 |
|---|---|---|
| A 工作区基础 | 配置、状态与执行上下文显式绑定项目 | 两项目交替装配不串状态，CLI / HTTP 兼容 |
| B 项目与会话闭环 | 项目登记、会话管理与持久化、项目 / 会话侧栏 | 刷新与重启后恢复已保存对话，运行归属和写冲突处理正确 |
| C 配置可见 | 设置面板展示有效值、来源与限制 | 展示结果与实际运行一致，错误路径也不泄漏凭证 |
| D 配置可编辑 | 闸门控制下保存项目非凭证设置 | 非法请求不改文件，保存失败可恢复，新运行使用新值 |
| E 整体验收 | 完整控制台体验与配套文档 | 回归既有流式、工具活动、停止和重连能力 |

## 9. 周期验收标准

1. 在 A、B 两项目间交替操作，会话、项目级记忆和运行状态归属正确；不能用 A 的请求误读或修改 B 的会话。
2. 已保存的会话在刷新浏览器、重启服务后仍可列出、打开和继续，消息顺序及工具调用 / 结果配对完整。
3. 切换项目不改变既有运行绑定；停止、重连和会话删除定位准确，冲突有明确结果。
4. 四级配置来源与新运行的解析结果一致；移除项目覆盖后正确显示回退值及来源。
5. 开关关闭、非允许来源、未知键、非法值、凭证键或外部修改冲突均显式失败，原配置保持完整。
6. 配置保存成功后当前运行保持旧快照，下一次运行使用新值；API 与 UI 如实表达生效时机。
7. 配置响应、错误、日志和审计不出现密钥明文；覆盖短密钥、多密钥与备份访问的负向验证。
8. 移除项目登记保留目录与项目数据；删除会话需要确认，不能静默覆盖正在进行的写入。
9. Epic 49 的流式、工具活动、停止、重连和来源校验无回归，入口限制在 UI 与文档中可见。
