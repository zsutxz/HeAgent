# ADR-003 · 参数化覆盖率口径 = touched-scope

> **状态**：accepted（Epic 63 retro 提案，2026-11-18 用户批准）
> **来源**：plan `tickets/epic-63-测试体系增强/tickets/story-63.8-parametrize-plan.md`；commit `abf96d9`
> **治理面**：后续「参数化覆盖率」类度量的口径

**Context.** Epic 63 的 Done when 写「参数化 >30%」，但既未定义分母（全套件？被触及文件？），也未定义分子（含 `parametrize` 的文件数？由参数化生成的用例数？）。本仓已有 52 个含 `parametrize` 的测试文件，若按全套件口径，一次局部收敛永远到不了阈值；若按文件数，则「一个文件里一条参数化」也能充数。

**Decision.** 参数化覆盖率按 **touched-scope** 口径度量：分母 = 本票改动的测试文件所收集到的用例数，分子 = 其中由 `parametrize` 生成的用例数。Epic 63 实测值 = 三文件 32 用例中 25 个参数化生成，**78%**；同时记录未被合并的散测簇（结构差异大、合并会牺牲可读性），不在票面外强推。代码量指标同口径（三文件 176→125、312→217、36→33 行）。

**Why.** 分母取 touched-scope 才能让「这次重构真的减少了多少重复」可度量且可复现，且不会因为历史遗留文件拉低分子分母而逼出为指标服务的机械合并；记录未触达簇则保留了「为什么这里有重复但没合并」的审计线索，避免下一条 story 重复勘察。
