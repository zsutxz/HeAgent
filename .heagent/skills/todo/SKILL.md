# todo

> `## Pattern` 只放一行纯词：`parse_skill_md` 会把该节之后所有非空行都并进 `pattern`（`skill_models.py:107-118`），
> 而 `pattern` 不是正则（`?` `|` `\.` 只当噪声词元）——说明文字写在本节之前的空档，不写在节内。

## Pattern
写 todo|记录到 todo|加入 todo|记到待办|整理待办|todo.md|待办清单

## Steps

### A. 文件契约

- 收集池 = `todo/todo.md`（**仓库根**下的 `todo/`，不在 `docs/` 里；以下路径都相对仓库根）：`## 待整理`（追加区）/ `## 已归档`。
- 主题文档 = `todo/solutions/<主题名>.md`（复杂主题用同名文件夹 + `README.md`）：按主题命名，禁按日期/ID，定后不改名；手写可改面。
- **先 refine 后方案**：每个主题文档开头固定 `## 细化（六项）`（标题 / 背景动机 / 验收判据 / 落点 / 规模 S·M·L / 风险与前置）；
  没有独立的 `refined.md`，也没有 `archive/` 日期快照。
- 条目 ID = `T-YYYYMMDD-N`（分配后不改）；原始行游标 = 行尾追加 `→ T-…`，不删不改用户原文。

### B. 收集模式（仅限用户点名 todo）

1. **触发闸门**：只有用户说出 `todo`／`写 todo`／`记录到 todo`／`加入 todo`／`记到待办` 才写；随口想法、缺陷线索、
   改进意见、「以后要记得」一律不落盘；判不准时最多问一句「要记进 `todo/todo.md` 吗？」。
2. 一条只写一件事、动词开头；保留原话硬约束，补 `（来源：…，记录：YYYY-MM-DD）`。
3. `file_edit` 定点插入 `## 待整理` 末尾（勿 `file_write` 覆盖用户手写行）；9p 上偶发 `OSError [Errno 22]`，原样重试 1–3 次即成功。
4. 与两节现有行同义查重：重复不新增，语义相同合并并保留最早日期。
5. 回读确认条数 +N，汇报分行：新增 N / 重复 N / 当前共 N。

### C. 整理模式（手工触发，不挂 cron）

1. 读三处：`todo/todo.md`、`todo/solutions/` 现有主题文档（是否已有同主题）、`docs/current` 票树与
   `_bmad-output/open-items.md`（查重）。无游标行必判，有游标行复核（没变化就不动）。
2. 四判定：**值得做** / **已完成**（须证据：文件、测试或命令输出）/ **不做**（须证据路径 `文件:行号`｜台账 ID｜
   命令输出，给不出就改判待裁决）/ **待用户裁决**。
3. 「值得做」四条全满足：产出可验证（一条命令 / 一次观测 / 一份 diff）、场景明确、规模 S ≤ 半天 / M 1–3 天 /
   L > 3 天（L 须给拆分建议）、不重复（已被票树或台账覆盖 ⇒ 判不做并给 ID）。
4. **先 refine（本技能的核心动作）**：在 `solutions/<主题名>.md` 写或更新 `## 细化（六项）`，位置在 `# <主题>`
   与来源行之后、其余小节之前；不写实现代码，不替用户决定方案。
5. 方案正文只在命中触发条件时续写：正文 > 40 行 / ≥ 2 段配置或命令 / 含选型对比（≥ 2 条路线）/ 需反复追加。
   六项里的验收判据与风险写**简版 + `见 ## 验收判据`**，不复制正文；不命中就只留六项（状态「草案」），不留空小节。
6. 回写游标：值得做行尾加 `→ T-…`；完成移入 `## 已归档` 写结论（一句话级不必建文档）；不做留原位加
   `（结论：不做 — 理由，YYYY-MM-DD）`。
7. 自校验：每个 `T-` 在 `todo.md` 都有来源行；无游标行数 == 汇报的「剩余未整理」；同一 ID 不散在多篇文档。
8. 汇报分行：细化 N 条（ID + 标题 + 路径）/ 不做 N 条（理由）/ 待裁决 N / 立即可做 Top3 / 剩余未整理 N；
   池子空或全已整理就明说「本轮无变化」，不动任何主题文档。

### D. 主题文档固定小节（顺序不变）

`# <主题>` → `> 来源：… T-… ｜ 更新：YYYY-MM-DD ｜ 状态：草案/进行中/已完成` → `## 细化（六项）`
→ `## 现状取证` → `## 方案`（已完成写「做了什么」）→ `## 验收判据`（已完成写实跑结果）
→ `## 风险与前置`（已完成写能力边界）→ `## 待用户裁决`（有才写）→ `## 变更记录`（日期 / 改了什么 / 依据）。

### E. 纪律

- **读入闸门**：用户没专门点名 `todo`／待办／`todo.md`／`solutions/` 时，忽略 `todo/` 下的所有清单——
  不读、不引用、不在汇报里提，也不把里面的条目当候选行动推荐；整理模式同样只由用户显式触发。
- 写入口径：只收用户点名 todo 的那一批；不把 `solutions/` 当收集处（手工新增一律进 `todo.md`）。
- 只产文档：不改 `src/`、`tests/`、票树状态、`_bmad-output/` 台账；值得开票的写进「待用户裁决」。
- 不挂定时任务（不要调 `cron_add`）；不再建 `refined.md`。
- `todo/` 已入库：改完按仓库提交纪律先呈报清单，不自行 commit。
- 路径用相对写法；`docs/` 内只能写代码路径、不能写 md 链接（`todo/` 在 docs_dir 外），
  改完跑 `tests/test_docs_links.py` 与 `mkdocs build --strict`。
- 主题文档不是票面、不写状态、不替代 plan；真开工按 bmad 立项进 `docs/<goal-id>/tickets/`。
