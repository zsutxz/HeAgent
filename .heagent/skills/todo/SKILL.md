# todo

> 收集**必须**由用户点名 todo 触发；只有 `## Pattern` 命中时才写 `docs/todo/todo.md`（详见 B.0 触发闸门）。
>
> 本节的词元会被 `parse_skill_md` 全量计入 `pattern`（`skill_models.py:107-118`），
> 故**只放一行纯词**：不写正则语法（`?` `|` `\.` 在词元匹配器里无正则语义）、不在这里加说明文字。

## Pattern
写 todo|记录到 todo|加入 todo|记到待办|整理待办|todo.md|待办清单

## Steps

### A. 文件契约（先读，别另起文件）

- 收集池 = `docs/todo/todo.md`，两节：`## 待整理`（追加区）/ `## 已归档`（完成或裁定不做）。
- **细化产出就是解决方案文件本身**：`docs/todo/solutions/<主题名>.md` 开头的 `## 细化（六项）` 段
  （标题 / 背景动机 / 验收判据 / 落点 / 规模 S·M·L / 风险与前置）。
- **没有 `docs/todo/refined.md`**（2026-11-25 用户裁定删除）：细化不单独成文件、不再有「重渲染产物」；
  每个主题文档**先 refine、后方案**，细化块永远在方案正文之前。
- 条目 ID = `T-YYYYMMDD-N`（N 从 1 起），**一经分配不再改**；同一事项跨日沿用旧 ID。
- 原始行游标 = 在该行行尾追加 `→ T-YYYYMMDD-N`；不删除、不改写用户原文。
- 主题文档 = `docs/todo/solutions/<主题名>.md`（复杂主题用同名**文件夹** + `README.md`）：
  **按主题命名、不按日期不按 ID**；纯手写可改面，不会被任何重渲染覆盖（见 E）。

### B. 收集模式（**仅限用户显式点名 todo 时**）

0. **触发闸门（先判，不满足就什么都不写）**：只有用户明确说出 `todo`／`写 todo`／`记录到 todo`／`加入 todo`／
   `记到待办` 这类**显式落盘指令**（也就是他这一句话里点名了 todo），才进入下面的收集流程。
   - 用户随口提的想法、缺陷线索、改进意见、被你追问出来的需求，**一律不写 `todo.md`**，只在当轮对话里回应或处置；
   - 「以后要记得」「这个得改」这类没有点名 todo 的话也**不算**触发；
   - 判不准时**不写**，最多回一句「要记进 `docs/todo/todo.md` 吗？」——宁缺不滥，误写比漏写更糟。

1. 从用户消息里抽出**原子事项**：一条只含一件事、以动词开头（`给 … 加 …` / `排查 …` / `把 … 改成 …`）；
   一句话含多个诉求就拆成多条，不要在一条里塞「并且」。
2. 保留用户原话里的硬约束（端口号、文件名、行为口径），只补「来源 + 记录日期」：
   `- [ ] <事项>（来源：<会话线索 / 文件 / 日志行>，记录：YYYY-MM-DD）`。
3. 追加到 `docs/todo/todo.md` 的 `## 待整理` 末尾：用 `file_edit` 做**定点插入**（不要 `file_write` 全量覆盖，
   会丢用户手写行）；容器 9p 上偶发 `OSError [Errno 22]`，原样重试 1–3 次即成功。
4. 查重：与 `## 待整理`、`## 已归档` 现有行做同义比对 —— 重复的不新增，只在汇报里点名「已存在（YYYY-MM-DD 记录）」；
   语义相同的多条合并为一条，保留最早记录日期。
5. 回读该节确认条数 == 追加前 + 新增；汇报分行分点：新增 N 条（逐条短句）/ 判为重复 N 条 / 当前共 N 条。

### C. 整理模式（手工触发：用户说「整理待办」/ 显式调用本技能；**不挂 cron**）

1. 读三份输入：`docs/todo/todo.md` 全文、`docs/todo/solutions/` 现有主题文档清单（每篇的 `## 细化（六项）`
   与状态行、判断该主题是否已有文档、避免重复建）、`docs/current` 指向的 `docs/<goal-id>/tickets/` 与
   `_bmad-output/open-items.md` 活动项（查重）；无游标的行 = 本轮新增（必判），有游标的行 = 复核（没变化就不动）。
2. 逐条判定四选一：**值得做** / **已完成**（须有证据：文件、测试或命令输出）/ **不做** / **待用户裁决**。
3. 「值得做」判据（全满足才建/更新主题文档）：
   - 产出可验证：能写成一条命令、一次观测或一份文件差异；
   - 场景明确：说得清「谁在什么时候需要它」，不是泛泛的「应该更好」；
   - 成本可控：规模判 S（≤ 半天）/ M（1–3 天）/ L（> 3 天），L 必须给拆分建议；
   - 不重复：已被票树或台账覆盖的改判「不做（已在票树 / 台账）」并给 ID。
4. 「不做」必须给证据路径（`文件:行号` / 台账 ID / 命令输出）；给不出证据的不得判不做，改判「待用户裁决」。
5. **先在主题文档里 refine（这是本技能的核心动作）**：新建或就地更新 `solutions/<主题名>.md` 的
   `## 细化（六项）`，六项缺一不可：标题 / 背景动机 / 验收判据（可执行命令或可观测现象）/ 落点（文件或模块）/
   规模 S·M·L / 风险与前置。**不写实现代码**，不替用户决定方案细节。
   细化块位置固定：`# <主题>` 标题与来源行之后、其余小节之前。
6. 需要方案正文时才续写（触发条件见 E.2）：`## 现状取证` / `## 方案` / `## 验收判据` / `## 风险与前置`。
   细化块里的「验收判据 / 风险与前置」写**简版 + 指针**（`见 ## 验收判据`），不复制正文（两处真相 = 漂移源）。
   触发条件不命中的，主题文档**只含 `## 细化（六项）`**（状态写「草案」），不写空小节占位。
7. 回写游标：值得做的行尾加 `→ T-…`；已完成的移入 `## 已归档` 并写 `（结论：YYYY-MM-DD …）`；
   不做的**留在原位**只追加 `（结论：不做 — 理由，YYYY-MM-DD）`，不删行。
8. 已完成 / 已定的条目：在同名主题文档里补「做了什么 + 证据命令 + 实跑数字」，`## 细化（六项）`标注
   「回溯填写」，并在 `## 变更记录` 追加一行。一句话级完成结论可不建文档，直接写在 `todo.md` 的
   `## 已归档` 行内。
9. 自校验三项，任一不符先修再汇报：① 每个 `T-` 编号都能在 `todo.md` 找到来源行；
   ② 汇报的「剩余未整理」数 == `## 待整理` 里无游标行数；③ 同一 ID 不在 `todo.md` 与多篇主题文档里重复出现。
10. 汇报分行分点：新增/更新细化 N 条（逐条 ID + 标题 + 主题文档路径）/ 判定不做 N 条（逐条理由）/
    待裁决 N 条 / 立即可做 Top3 / 剩余未整理 N 条。
11. 池子为空或全是已整理行：不动任何主题文档，汇报里明说「本轮无变化」。

### D. 纪律

- **写入口径（2026-11-25 用户裁定）**：只做「用户点名 todo」的那一批记录 —— 没点名 todo 的想法、缺陷线索、
  改进建议一律不进 `docs/todo/todo.md`，也不留「顺手记一条」的余地。
- 只产文档：不改 `src/`、`tests/`、票树状态、`_bmad-output/` 台账；发现值得开票的条目写进「待用户裁决」。
- **不把 `solutions/` 当待办输入**：手工新增一律进 `todo.md`；主题文档是细化的**落点**，不是收集处。
- **不允许再建 `refined.md`**：细化一律落在主题文档的 `## 细化（六项）`（2026-11-25 用户裁定）。
- `docs/todo/` 已纳入版本库（2026-11-25 用户裁定）：改完按仓库提交纪律先呈报清单，不自行 commit。
- 整理模式**不挂定时任务**（2026-11-25 用户裁定「不要挂」）：不要调用 `cron_add`，只在被显式要求时整理。
- 路径用相对写法（`docs/todo/todo.md`）；本仓工具对 `/workspace/...` 绝对写法偶发被路径围栏拒。

### E. 主题文档落盘（`solutions/`，按主题命名；**先 refine，后方案**）

> 动机：细化（值不值得做、规模、验收判据）与方案正文（配置片段、命令串、选型对比、排障历史）是同一件事的
> 两个阶段，放同一个**主题**文件里才不会漂移；主题名指路，用户一眼能找到。

1. **命名（唯一形态：主题名）**：
   - 单文件：`docs/todo/solutions/<主题名>.md`，例 `内网穿透.md`、`多项目并行开发验证.md`；
   - 主题复杂 / 要多份附件（脚本、配置样例、多份备选方案、验收记录）：`docs/todo/solutions/<主题名>/`
     + 正文 `README.md` + 附件同目录并列；
   - **禁止**按日期或 ID 命名（`2026-11-25.md`、`T-20251125-1-xxx.md` 都不行）：日期没有检索价值、
     ID 与主题对不上；ID 只活在 `todo.md` 的游标与主题文档的来源行里。
   - 主题名一经确定就不改名（改名断链）；确需更名时同批改完所有引用并跑 `tests/test_docs_links.py`。
2. **建文档时机 + 方案正文触发条件**：
   - 判为「值得做」的条目**必建**主题文档，且**首段就是 `## 细化（六项）`**（细化先做，方案后写）；
   - 方案正文（`## 现状取证` / `## 方案` / `## 验收判据` / `## 风险与前置`）在任一条件下续写：
     正文将超过 **40 行**；含 **≥ 2 段**可执行配置 / 命令；含**选型对比**（≥ 2 个候选路线）；
     会被**反复追加**（排障记录、验收结果、变更历史）；
   - 触发条件都不成立就**只留细化六项**，不写空小节（空占位会让人误判已写过方案）。
3. **固定小节（顺序不变）**：
   `# <主题>` → `> 来源：[todo.md](../todo.md) 的 T-… ｜ 更新：YYYY-MM-DD ｜ 状态：草案/进行中/已完成`
   → `## 细化（六项）`（`### 1. 标题` … `### 6. 风险与前置`）
   → `## 现状取证` → `## 方案`（已完成的写「做了什么」）→ `## 验收判据`（已完成的写实跑结果）
   → `## 风险与前置`（已完成的写能力边界 / 已知缺口）→ `## 待用户裁决`（有才写）
   → `## 变更记录`（表格：日期 / 改了什么 / 依据）。
4. **一份真相**：细化块的验收判据 / 风险与前置写简版 + `见 ## 验收判据`；正文只在不命中 E.2 时缺席。
   **不复制同一段文字到两处**。
5. **`todo.md` 侧留指针**：值得做 / 已完成的条目行尾或 `## 已归档` 结论里指向
   `[`solutions/<主题名>.md`](solutions/<主题名>.md)`。细化块不复制进 `todo.md`。
6. **写权归属**：主题文档是手写可改面（用户可直接改），本技能只在「首次创建 / 补细化六项 / 追加变更记录 /
   补验收结果」时写它；**没有任何重渲染会覆盖它**（`refined.md` 已删除）。
7. **链接口径**：`docs/todo/` 内互引一律相对路径（`solutions/X.md`、`../todo.md`）；中文文件名可直接用，
   但改完必须跑 `tests/test_docs_links.py`（4 例）与 `mkdocs build --strict` 复核。
8. **按需建目录**：没有「值得做」条目的就不建 `solutions/` 目录；不要留空目录或占位文件。
9. **与票树边界**：主题文档不是票面、不写状态、不替代 plan；真开工时按 bmad 立项进
   `docs/<goal-id>/tickets/`，主题文档只作背景链接被引用。
