## 细化（六项，已完成条目回溯填写）

### 1. 标题

补一套真栈判据，证明 HeAgent **同时**支持多个项目并行开发（不是排队、不串话、会话与根目录互不可见）。

### 2. 背景动机

- 项目注册表、控制台协议、WS 项目通道各有替身层判据（见 `## 现状取证` 前四层），但 run 推进由用例手动驱动
  ⇒ 证不了「两个 run 真的同时在跑」。
- 并行能力是 A41 worktree 隔离之后的主线承诺，缺一格真栈判据就等于无判据。

### 3. 验收判据（简版；实跑结果见 `## 验收判据`）

- `pytest tests/network/test_multi_project_live.py -q` 两例全绿：两项目同时 in-flight → 各自 `done`、
  事件 `seq` 不交叉、会话按项目根隔离；`max_total_inflight=1` 时撞 `total_inflight_limit`。
- 反证：把「名额按项目分档」退化成全局计数 → 两例均红。

### 4. 落点

- `tests/network/test_multi_project_live.py`（新增两例，真 `HttpRunService` + 真 `AgentLoop` + 真 listener）。
- 夹具模板与实跑数字：本文件 `## 方案` / `## 验收判据`。

### 5. 规模

- M（1–3 天）：夹具复用 `test_ws_remote_flow_live.py` 的真栈形态，主要成本在「两个 run 同时停在 running」
  的确定性窗口与交叉反断言。

### 6. 风险与前置（简版；能力边界见 `## 风险与前置`）

- 前置：`websockets` 客户端可用（已有）、闸门 provider（`asyncio.Event`）能造确定性窗口。
- 边界：每项目在途上限默认 1 ⇒ 并发随项目数线性；服务级总额 `HTTP_MAX_TOTAL_INFLIGHT` 默认 0（不限）。

## 现状取证（分层覆盖，逐层独立可跑）

| 层 | 判据落点 | 证什么 |
| --- | --- | --- |
| 注册表层 | `tests/test_projects.py` | 登记 / 去重 / 路径规范化 / 上限 / 坏表 fail-soft |
| 控制台协议层 | `tests/network/test_http_console_projects.py` | HTTP 项目路由与稳定错误码 |
| WS 项目通道（端口替身） | `tests/network/test_ws_project_admission.py` | 名额分档、跨项目不串话、并发交叉计数 |
| WS 真栈 · 单项目 | `tests/network/test_ws_remote_flow_live.py` | ADR-005 五步在真 listener + 真 `AgentLoop` 上跑通 |
| **WS 真栈 · 多项目** | `tests/network/test_multi_project_live.py` | 两项目**同时** in-flight → 各自终态、事件不交叉、会话与根目录互不可见 |

替身层能证「不串话」，但 run 推进由用例手动驱动 ⇒ 证不了「两个 run 真的同时在跑」；第五层补的正是这一格。

## 方案（本次交付了什么）

新增 `tests/network/test_multi_project_live.py`（2 例，`websockets` 真握手，真 `HttpRunService` + 真 `AgentLoop`）：

1. `test_two_projects_run_concurrently_to_completion` —— 断言链五步：
   - 两条 ack 都是 `running` 且 `active_runs == 2`（并行受理，不是排队）；
   - 两条事件流 `seq` 各自从 1 连续、终态 `done`，且只携带**自己** prompt 的答案（反向交叉断言）；
   - 两条记录 `session_id` 不同，会话文件各落各自项目根，交叉目录里查不到对方；
   - `console.list_sessions()` 按项目隔离；
   - 终态后 `active_runs` 归零（名额归还），且 provider 两次调用 prompt 分别来自两个项目。
2. `test_total_inflight_cap_bounds_concurrent_projects` —— `max_total_inflight=1` 时 B 撞
   `total_inflight_limit`（服务级总额），与按项目的 `run_conflict` 是两个码、两条判据。

夹具形态（可复用模板）：`HttpAgentHandler` + `HttpRunService` + `HttpProjectConsole(handler_factory=handler.for_workspace)`
+ `WsServer(project_service=_project_channel(console))`，`port=0` 起真 listener，`provider` 用闸门阻塞
（`asyncio.Event`）造「两个 run 同时停在 running」的确定性窗口。

## 验收判据（实跑结果）

```bash
pytest tests/network/test_multi_project_live.py -q                 # 2 passed / 2.59 s
pytest tests/network/test_ws_project_admission.py \
       tests/network/test_ws_remote_flow_live.py -q                # 10 passed / 3.12 s（同面不回归）
ruff check / ruff format --check（新文件）                          # All checks passed / already formatted
```

- 反脆弱反证：把「名额按项目分档」退化成全局计数重跑 → 两例均红 ⇒ 判据**非恒真**。
- 门禁口径：`mypy src`（tests 不进门禁）；新测试文件在 `tests/` 下额外跑 `ruff` 两项。

## 风险与前置（能力边界，不是缺陷）

- 每项目在途上限 `HTTP_MAX_INFLIGHT_RUNS` 默认 1 ⇒ 并发随项目数线性；服务级总额
  `HTTP_MAX_TOTAL_INFLIGHT` 默认 0（不限），显式设 N 后所有项目加总受 N 约束（先撞谁按谁拒）。
- 「一个 `HttpAgentHandler` = 一个项目根」是不变量：`for_workspace` 按项目重建 engine / 记忆 / 会话存储，
  跨项目零共享可变状态；共享的只有 `provider`（连接参数）与用户级全局技能根。
- 未覆盖（下一轮可补）：项目**移除时**在途 run 的处置、跨项目并发下的连接层上限（`HTTP_MAX_CONNECTIONS`
  不随项目数放大）、多项目 + cron 推送的交叉。
