# 调研 Claude Code 最新功能与学习资料

维护一份基于当前证据的 Markdown 学习文档，保存为 `news/learningclaude.md`。覆盖四块内容：Claude Code 与 Claude 模型的最新功能与新闻、Claude Code 基础用法、最佳实践、官方教程与视频资源（视频给链接即可）。

## 检查点与默认路径

- 默认输出路径固定为 `news/learningclaude.md`，与技能本体所在目录（`.claude/skills/learningclaude/`）无关，不得写往其他位置。
- 开工先核实本机当前日期，所有"最新"判断以本机日期为准；文档头部必须写生成日期。

## 工作流程

1. **来源优先级**：只用可核验来源，按序取用：
   - 官方一手（最高优先）：Claude Code 官方文档（code.claude.com/docs）、官方 changelog（GitHub `anthropics/claude-code` 的 CHANGELOG.md 与 releases）、Anthropic 官方新闻/工程博客（anthropic.com/news、anthropic.com/engineering）、官方模型页与定价页、官方 YouTube / 开发者频道。
   - 高可信次级（交叉核对用）：官方 GitHub issues/discussions、可信技术媒体、Hacker News、r/ClaudeAI。
   - 每个引用来源记录 URL 与访问日期；搜索摘要不能单独作为事实依据。
2. **采集范围**：
   - 版本与功能：近两周 changelog 条目、releases、官方博客新文。
   - 模型动态：新模型/新版本、能力与定价变化、弃用公告。
   - 基础用法：安装与更新、常用 CLI 命令、斜杠命令、权限模式、CLAUDE.md、hooks、MCP、subagents、skills、/config、headless 模式。
   - 最佳实践：官方 best practices 文章 + 社区验证经验，区分"官方建议"与"社区经验"。
   - 教程与视频：官方教程文档链接、视频只给链接（标题 + 平台 + 链接），不必转写内容。
3. **文档固定结构（顺序不得调整，重点更新功能必须在最后）**：
   1. H1 + 生成日期 + 来源说明
   2. `## Claude Code 简介`（一段话 + 适用场景，稳定内容）
   3. `## 基础用法`（安装、常用命令表、斜杠命令、配置文件体系、权限模式）
   4. `## 最佳实践`（CLAUDE.md、权限与安全、上下文管理、并行与自动化）
   5. `## 官方教程与视频`（链接清单）
   6. `## 重点更新功能`（**必须放最后**；按日期倒序列新版本/新功能/新闻条目，每条带日期、一句话说明、来源链接）
4. **增量更新语义**：已存在 `news/learningclaude.md` 时先读它。前五个部分保留仍有效内容、更新过时说法；`## 重点更新功能` 节内新条目**插入到该节顶部**（日期倒序），已有条目原样保留，不悄悄删除有价值历史；条目超过约 30 条时可把最老的移到"更早更新"折叠小节，不得直接删。
5. **失败处理与停止条件**：
   - 官方文档/changelog 全部不可访问 ⇒ 在文档头部"来源说明"如实记录失败，仍可基于本地已有内容做结构维护，但不得凭模型记忆补写新版本号或新功能；当日无新信息且结构完好 ⇒ 允许只更新检查日期后结束。
   - 任何版本号、功能、日期写进文档前必须落到本次访问的具体来源；查不到就写"未核实"，绝不编造。
   - 触发边界：本技能只维护这一个文档，不扩展成 Claude API 手册或无关工具目录。
6. **语言与格式**：简洁中文撰写；命令、配置、代码用代码块；链接用 Markdown 链接并附访问日期。

## 研究规范

- 区分"官方发布事实"与"社区传言"：仅有社区来源的功能标注"待核实"，不得写成已发布事实。
- 版本对比以 changelog 原文为准，不要只依赖媒体转述。
- 报告局限：文末注明未能访问的来源、未追读的材料。
