# 调研 Claude Code 最新功能与学习资料（三件套）

维护 `news/learningclaude/` 目录下三个分层文档，与技能本体所在目录无关：

| 文件 | 定位 | 内容 |
|---|---|---|
| `claude_base.md` | 基础用法·稳定层 | 简介、安装与启动、常用斜杠命令、快捷键、配置文件体系、权限模式、官方教程与视频 |
| `report.md` | 高级与最新方法·进阶层 | 最佳实践、新功能的用法与技巧（每条注明引入版本/日期/来源；弃用标注替代，不删） |
| `log.md` | 版本与新闻记录·时序层 | 新闻条目（日期倒序）、版本条目（版本号倒序）、模型动态速览、复查记录与局限（只追加） |

**分工判据**：稳定且入门必需 → claude_base；「怎么用好/新东西怎么用」→ report；「发生了什么/哪个版本」→ log。同一内容只存一处，三文件交叉链接。

## 检查点与默认路径

- 三路径固定为 `news/learningclaude/{claude_base,report,log}.md`，不得写往其他位置。
- （2026-11-03 结构）旧单文件 `news/learningclaude.md` 已按三分法迁移并移除，**不得再写它**。
- 开工先核实本机当前日期，所有"最新"判断以本机日期为准；各文件头部写最近更新日期。

## 工作流程

1. **来源优先级**：只用可核验来源，按序取用：
   - 官方一手（最高优先）：Claude Code 官方文档（code.claude.com/docs）、官方 changelog（GitHub `anthropics/claude-code` 的 CHANGELOG.md 与 releases）、npm registry（版本发布时间权威源）、Anthropic 官方新闻/工程博客（anthropic.com/news、anthropic.com/engineering）、官方模型页与定价页、官方帮助中心发布说明、官方 YouTube / 开发者频道。
   - 高可信次级（交叉核对用）：官方 GitHub issues/discussions、可信技术媒体、Hacker News、r/ClaudeAI。
   - 每个引用来源记录 URL 与访问日期；搜索摘要不能单独作为事实依据。
2. **采集范围**：
   - 版本与功能：近两周 changelog 条目、releases、npm registry 发布时间、官方博客新文。
   - 模型动态：新模型/新版本、能力与定价变化、弃用公告。
   - 基础用法：安装与更新、常用 CLI 命令、斜杠命令、权限模式、CLAUDE.md、hooks、MCP、subagents、skills、/config、headless 模式。
   - 最佳实践与新方法：官方 best practices 文章 + 社区验证经验，区分"官方建议"与"社区经验"；新版本引入的能力写清「怎么用」。
   - 教程与视频：官方教程文档链接、视频只给链接（标题 + 平台 + 链接），不必转写内容。
3. **三文件固定结构（顺序不得调整）**：
   - `claude_base.md`：H1 + 最近更新日期 + 定位与交叉链接 → 简介 → 基础用法（安装与启动/常用斜杠命令/常用快捷键/配置文件体系/权限模式）→ 官方教程与视频。**只在内容失效或新增基础能力时改动**。
   - `report.md`：H1 + 最近更新日期 + 定位与交叉链接 → 最佳实践（官方口径与社区经验分标）→ 高级与最新方法（从 log 沉淀「怎么用」面，每条注明引入版本/日期/来源；功能弃用时改标「已弃用」并给替代，不直接删）。
   - `log.md`：H1 + 最近更新日期 + 来源清单 + 说明 → 新闻条目（**插顶部**，日期倒序）→ 版本条目（**插顶部**，版本号倒序）→ 模型动态速览 → 复查记录与局限（**每轮复查追加一条**，不改旧记录）。
4. **增量更新语义**：三文件都先读后写。log 新条目插顶部、旧条目原样保留（条目超过约 30 条时把最老的移入"更早条目"折叠小节，不得直接删）；report 过时方法改标注「已弃用」并给替代，不删除；claude_base 失效内容就地更正并注明核实日期。
5. **失败处理与停止条件**：
   - 官方文档/changelog 全部不可访问 ⇒ 在 log.md 头部"来源清单"如实记录失败，仍可基于本地已有内容做结构维护，但不得凭模型记忆补写新版本号或新功能；当日无新信息且结构完好 ⇒ 允许只在 log.md 追加一条复查记录后结束。
   - 任何版本号、功能、日期写进文档前必须落到本次访问的具体来源；查不到就写"未核实"，绝不编造。
   - 触发边界：本技能只维护这三个文档，不扩展成 Claude API 手册或无关工具目录。
6. **语言与格式**：简洁中文撰写；命令、配置、代码用代码块；链接用 Markdown 链接并附访问日期。

## 研究规范

- 区分"官方发布事实"与"社区传言"：仅有社区来源的功能标注"待核实"，不得写成已发布事实。
- 版本对比以 changelog 原文为准，不要只依赖媒体转述。
- 报告局限：log.md 文末复查记录注明未能访问的来源、未追读的材料、取源方式的坑（如 web_reader 缓存）。
